# ADR-0001：改訂への対策は、AI の方式より文書の版管理を優先する

- 状態：採用
- 日付：Git のコミット日時を正とする
- 関連：[検証結果](../docs/40-local-ai-env/rag-vs-llmwiki-verification.md)

## 背景

資料の改訂を AI に正しく反映させたい。RAG と LLM Wiki の両方で、改訂資料を追加したときの挙動を検証した。

## 検証で分かったこと

- RAG：改訂資料が検索に入らない質問では古い値で答え、引用の判定も正常に見えた
- LLM Wiki（8B 級）：矛盾は検出できたが、Wiki への反映は不安定で、無関係な記述を消すこともあった
- どちらの方式でも、旧版と改訂版が参照対象に並んでいる限り、古い値で答える可能性が残る

## 決定

改訂への対策は、AI の方式の工夫より先に、文書側の版管理で行う。

1. 改訂は差分文書ではなく、本体を改版して版数を付ける
2. 旧版は AI の参照対象（RAG の索引、Wiki の取り込み元）から外す
3. 差分文書を残す場合は、変更点ごとに分け、対象の規約 ID を見出しに入れる

## 結果

- 良い点：AI の方式やモデルに依存せず効く。運用ルールで実現でき、追加開発が要らない
- 注意点：改版の手順を守る運用負荷がかかる。旧版を参照したい場面のために、版管理システム（Git など）で履歴をたどれるようにしておく
